## 1. 概要

### 1.1 アプリ概要

ローカル音楽ファイルを対象に、曲の指定区間のみを再生しながら次々と曲を切り替えていく音楽プレイヤーアプリ。

### 1.2 コンセプト

> 忘れていた曲に、次々と出会い直す体験

- 短時間で多くの楽曲を再生する
- 懐かしい曲・埋もれた曲を再発見する
- 作業用BGM・流し聴き用途にも使える

### 1.3 コア価値

- 時短で多くの曲を聴ける
- 懐かしい曲との再会
- 流れを止めない再生体験

---

## 2. ターゲットユーザー

- ローカルに大量の音楽を保存しているユーザー
- 昔の楽曲をよく聴いていたユーザー
- フル再生ではなく部分的に楽しみたいユーザー

---

## 3. 対応プラットフォーム・制約

- Android のみ
- ローカルファイルのみ対応（ストリーミング非対応）
- ネットワーク接続不要

### 3.1 メディアアクセス権限（決定：2026-09-02）

- Android 13 以降は `READ_MEDIA_AUDIO`、それ以前は `READ_EXTERNAL_STORAGE` を使用する
- 初回起動時に権限をリクエストする
- 拒否された場合は説明画面を表示し、設定アプリへの導線を用意する

## 4. コア機能

### 4.1 再生機能

- ローカル音楽ファイルの再生
- 再生 / 停止 / 次の曲 / 前の曲
- シャッフル再生
- リピート再生（OFF → 全曲リピート → 1曲リピート の3状態。普通のプレイヤー準拠）

### 4.2 区間再生機能（メイン機能）

**パラメータ**

- 再生開始位置（秒）
- 再生時間（秒）

**指定方式**（決定：2026-09-02）

- 秒指定（絶対値）と、曲の長さに対する相対指定（％）の両方に対応する
- 内部的には「その曲での実効的な開始位置・再生時間を解決する関数」を必ず経由して値を取得する設計とし、秒／％の差はこの層で吸収する
- UI露出は 秒＝Phase 1、％＝Phase 2 を目安とする
- 秒指定が曲の長さを超える場合の扱いは未決定（→ 15章）

**設定スコープ**（決定：2026-09-02）

- 区間設定はキュー全体で共通の**全体設定**を使用する
- プレイヤー画面のスライダー操作は、常に**全体設定の変更**として扱う（曲ごとの個別設定を暗黙に作らない）

**曲ごとの個別設定（保留・Phase 3 検討候補）**

- 実装するか自体が未決定。ややこしさに対して得られる体験が見合わないため、当面スコープ外とする
- 実装する場合のルール（決定済み）
  - 優先順位：**曲ごとの個別設定 > 全体設定**
  - 適用されるのは **RUSH ON のときのみ**。RUSH OFF 時は個別設定の有無にかかわらずフル再生する（→ 4.3）
  - 個別設定の作成は明示操作（長押し／「この曲に固定」等）に限る
- 実装しない場合でも、区間の値は常に「その曲での実効値を解決する関数」経由で取得する設計にしておき、後から差し込めるようにする

**動作**

- 指定した区間のみを再生し、終了後に次の曲へ遷移する

**境界処理**（決定：2026-09-02）

- 開始位置＋再生時間が曲の長さを超える場合：超過分は再生せず、**曲の終端でフェードアウトして次の曲へ**遷移する
- 開始位置が曲の長さを超える場合：**0秒（曲の先頭）から**再生する

### 4.3 RUSHモード（自動スキップ）

本アプリの中心となる再生モード。UI上の `Skip` トグルはこのモードのON/OFFを指す。

**RUSH ON（デフォルト）**

- 区間再生を有効にし、区間終了時にフェードアウトして次の曲へ自動遷移する
- 曲ごとの個別設定があればそちらを優先して適用する（→ 4.2 設定スコープ）

**RUSH OFF**

- 区間再生を無効にし、通常の音楽プレイヤーとして曲を**最初からフル再生**する
- 開始位置へのシークも行わない
- 曲ごとの個別設定があっても無視する
- 曲が最後まで再生されたら次の曲へ遷移する

**再生中に ON/OFF を切り替えた場合**（決定：2026-09-02）

- 切り替えは**次の曲から適用**する（シャッフルボタンと同じ感覚）
- 再生中の曲を区間の開始位置へシークし直すことはしない
- ただし **OFF にした場合のみ**、再生中の曲の区間カットも即座に解除し、そのまま最後まで再生する（シークはしない）

### 4.4 フェードアウト（必須）

- 再生終了直前に音量を徐々に下げ、自然な遷移を実現する
- 曲は重ならない（疑似クロスフェード）
- フェード時間：1〜5秒（デフォルト2秒）
- **Length より Fade が長い場合はクランプする**（決定：2026-09-02）
  - 実効フェード時間 = `min(設定値, Length ÷ 2)`
  - 例：Length=3秒 / Fade=5秒 → 実効フェード 1.5秒

## 5. キュー管理

### 5.1 キュー生成モード（排他）

- 全曲
- アーティスト（複数選択可）
- アルバム（複数選択可）

生成の導線はライブラリ画面の選択モードに統合する（→ 10.3）。

### 5.2 キュー生成ルール

- 選択条件に一致する楽曲をすべて追加する
- 同一楽曲の重複は排除する

### 5.3 再生終了時の挙動

- 通常時：キューの最後まで再生後、停止
- リピートON時：キューの先頭から再生

## 6. シャッフル再生

「シャッフルにしても同じ曲ばかり流れ、大半の曲が一生再生されない」問題の解消を目的とする。
RUSHモードとは**独立した機能**であり、RUSH ON / OFF のどちらでも同じように動作する。

### 6.1 基本仕様（普通のプレイヤー準拠）

- キュー内の曲から**順列を1つ生成**して順に再生する（再生ごとに独立抽選する方式は採らない）
- 1巡内で同一曲の重複なし
- シャッフルON/OFFの切り替えは**次の曲から適用**する（再生中の曲はそのまま継続）
- シャッフルON中の「前の曲」は**再生履歴を遡る**（元の並び順の前の曲ではない）
- シャッフルOFF時の並び順は、再生元となった一覧の表示順に従う（例：楽曲タブなら曲名順）

### 6.2 1巡状態の永続化（本アプリの肝）

- 生成した順列と現在位置（カーソル）を、**アプリ再起動をまたいで保存**する
- 起動時は保存済みの順列とカーソルを復元し、続きから再生する
- 1巡し切るまで、既に再生した曲は再び選ばれない
- これにより「毎回シャッフルし直して順列の先頭付近だけを聴く」状態を防ぐ

**保存単位**

- キューの生成条件ごとに順列を保持する（全曲 / アーティスト選択 / アルバム選択 など）
- 別のキューを再生してから戻っても、元のキューの順列と位置は失われない
  （※これにより旧「シャッフル状態の保持」仕様は自動的に満たされる）

**ライブラリが変化したとき**

- 削除された曲：順列から取り除く
- 追加された曲：順列の**未消化部分にランダムに挿入**する（新しく入れた曲がすぐ出てくるように）

**1巡し終わったとき**

- リピートON：順列を作り直して2巡目に入る
  - カーソルを0に戻す実装とコストが変わらないため、多様性が出る「作り直し」を採用する
  - 2巡目の先頭が1巡目の末尾と同じ曲になった場合は引き直す（同じ曲が2回続くのを防ぐ）
- リピートOFF：停止する

### 6.3 進捗の可視化

- 現在の1巡の進捗（例：`109 / 982`）をプレイヤー画面に表示する
- 「ライブラリをちゃんと一周できている」ことを可視化する

## 10. UI設計

### 10.1 画面構成

普通の音楽プレイヤーとしての使用感は **Pulsar** をベースとする。

- ライブラリ画面（タブ切り替え：アーティスト / アルバム / 楽曲 / プレイリスト）
  - キュー作成はこの画面の**選択モード**に統合する（専用画面は設けない）
- プレイヤー画面（再生中画面）
- 設定画面
- ミニプレイヤー（常時表示）

### 10.2 プレイヤー画面（メイン）

**概要**：再生・設定をすべて集約した中心画面

```
┌──────────────────────┐
│  ← Queue / 設定       │
├──────────────────────┤
│                      │
│      🎵 曲名          │
│   Artist / Album     │
│                      │
│    ─────────────     │
│    00:20 / 00:55     │
│    ─────────────     │
│                      │
│   [⏮] [▶/⏸] [⏭]      │
│                      │
│  Shuffle: ON         │
│  Skip: ON            │
│                      │
├──────────────────────┤
│ ▶ 区間設定           │
│ Start :  [====●----] 20s
│ Length:  [====●----] 35s
│ Fade  :  [==●------] 2s
│                      │
├──────────────────────┤
│ ▶ Queue Info         │
│ Mode : Artist (3)    │
│ Tracks: 128曲        │
└──────────────────────┘
```

**要素**

| グループ | 内容 |
|---|---|
| 再生情報 | 曲名 / アーティスト名・アルバム名 / 再生区間（開始・終了） |
| 再生操作 | 前の曲 / 再生・停止 / 次の曲 |
| 状態表示 | シャッフル ON/OFF / スキップ ON/OFF |
| 区間設定（スライダー） | 開始位置（秒） / 再生時間（秒） / フェード時間（秒） |
| キュー情報 | 現在のモード（全曲 / アーティスト / アルバム） / 曲数 / 1巡の進捗（例：109 / 982） |

**再生中画面としての一般的な要素**（Pulsar 準拠）

- 大きなアートワーク表示
- シークバー（現在位置 / 全体長）とシーク操作
- シャッフルボタン、リピートボタン（OFF / 全曲 / 1曲）
- お気に入り（ハート）
- キュー内容の表示
- 曲情報の表示（アルバム名、フォーマット情報など）

### 10.3 キュー作成（ライブラリ画面の選択モード）

**概要**：専用画面は設けず、ライブラリ画面上の**長押し → 複数選択**でキューを作る。
アーティストやアルバムをまとめて選んで「簡易プレイリスト」として流す使い方を主眼に置く。

**導線**

1. アーティスト / アルバム / 楽曲タブで項目を**長押し**すると選択モードに入る
2. 以降はタップで複数選択できる（選択数をヘッダーに表示）
3. アクションを選ぶ
   - **再生**：選択対象の楽曲でキューを生成し、プレイヤー画面へ遷移して再生を開始する
   - **プレイリストとして保存**：ユーザー作成プレイリストに保存する（Phase 2）

```
┌──────────────────────┐
│ ✕  3件選択     ▶  ⋮ │  ← 選択数 / 再生 / その他
├──────────────────────┤
│ ☑ Artist A     22曲  │
│ ☑ Artist B     16曲  │
│ ☐ Artist C      4曲  │
│ ☑ Artist D      8曲  │
└──────────────────────┘
```

**仕様**

- 選択条件に一致する楽曲でキューを生成する（同一楽曲の重複は排除 → 5.2）
- 複数選択は同一タブ内で行う
- 「全曲」キューは選択モードを使わず、楽曲タブのシャッフルFABから生成する
- キュー生成後はプレイヤー画面へ自動遷移し、再生を開始する（決定：2026-09-02）

### 10.4 ライブラリ画面

**概要**：端末内の楽曲をタブで切り替えて閲覧・再生する。Pulsar の構成をベースとする。

```
┌──────────────────────┐
│ ≡  RE:TR4CKS   🔍  ⋮ │
├──────────────────────┤
│ アーティスト│楽曲│PL  │  ← タブ
├──────────────────────┤
│                      │
│  （タブごとの一覧）   │
│                      │
│                 (⤮)  │  ← シャッフル再生FAB
├──────────────────────┤
│ 🎵 曲名        [⏸][⏭]│  ← ミニプレイヤー
└──────────────────────┘
```

**タブ構成**

| タブ | 内容 |
|---|---|
| アーティスト | アートワーク付きグリッド。アーティスト名 / アルバム数 / 曲数を表示 |
| アルバム | アートワーク付きグリッド。アルバム名 / アーティスト名 / 曲数を表示 |
| 楽曲 | 全曲のリスト。曲名 / アーティスト名 / 再生時間を表示 |
| プレイリスト | 自動プレイリスト（お気に入り / 最も再生された / 最近再生された / 最近の追加曲）＋ ユーザー作成プレイリスト |

**仕様**

- タブは設定で**並び替え・表示非表示**を変更できる（→ 10.7）
  - タブ候補：アルバム / アーティスト / フォルダ / ジャンル / 楽曲 / プレイリスト
- 項目を**長押し**すると選択モードに入り、複数選択からキューを作成できる（→ 10.3）
- 一覧から曲をタップすると、**その一覧をキューとして**再生を開始する（普通のプレイヤー準拠）
  - RUSH ON なら区間再生、RUSH OFF ならフル再生（→ 4.3）
- シャッフル再生用のFABを配置する
- 検索機能を持つ

### 10.5 ミニプレイヤー

**概要**：全画面共通で表示される簡易プレイヤー

```
┌──────────────────────┐
│ 🎵 曲名        [⏸] [⏭] │
└──────────────────────┘
```

**仕様**

- 再生 / 停止
- 次の曲へ
- タップでプレイヤー画面へ遷移

### 10.6 設定画面

Pulsar を参考にした構成。MVPで必須のものと、あれば嬉しいものを分けて考える。

**優先度：高**

- タブ項目の変更（表示するタブの選択と並び替え）
- 除外するフォルダ（着信音やボイスメモを弾く）
- 短い曲を除外する（例：15秒未満）
- 一覧の並べ替え順

**優先度：中〜低**

- RUSHのデフォルト値（Start / Length / Fade）
- ロック画面にアートワークを表示
- ギャップレス再生

### 10.7 UI設計方針

- **シンプル設計**：画面数を最小限にする、迷わない操作を優先
- **プレイヤー中心**：設定はプレイヤー画面に集約し、画面遷移を減らす
- **直感操作**：スライダーによる秒数調整、ワンタップ操作
- **情報最小化**：必要な情報のみ表示し、ノイズを排除

## 13. 技術方針

調査日：2026-09-02

### 13.1 基本構成

| 領域 | 採用 | 備考 |
|---|---|---|
| フレームワーク | Expo (SDK 57) / React Native | New Architecture 必須の世代 |
| ビルド | **development build**（Expo Go 不可） | ネイティブモジュールを含むため |
| 再生エンジン | **expo-audio** | 公式・無料・New Arch対応・活発に更新 |
| ライブラリ走査 | **expo-music-library** | 曲/アルバム/アーティスト/ジャンル/アートワークを取得 |
| キュー・シャッフル管理 | **自前実装** | 独自の順列＋永続化が必要なため（→ 6章） |
| 通知の「次の曲」 | **要対応**（→ 13.3） | expo-audio に該当機能が無い |

### 13.2 再生ライブラリの選定理由

候補の比較（2026-09-02 時点）:

| ライブラリ | ライセンス | 状態 | 通知の次/前ボタン |
|---|---|---|---|
| **expo-audio 57.0.4** | 無料 | 公式・活発（当日も更新） | ✗ ±10秒シークのみ |
| @rntp/player (RNTP V5) 5.9.2 | 商用 €999/年〜 | 活発 | ✓ |
| react-native-track-player (V4) 4.1.2 | Apache-2.0 | **凍結**（2026-03が最終） | ✓ |
| react-native-audio-pro | - | **アーカイブ済み** | - |

**expo-audio を採用する理由**

- RNTP V5 は V5 から商用ライセンス（€999/年〜）。個人・教育利用は無料だが、ストア公開が「personal use」に当たるかは grey zone のため、土台には据えない
- RNTP V4 は無料かつ機能は揃うが、V5 が New Architecture 前提の全面書き換えとして分岐したため V4 は凍結済み。2026年に新規で始めるプロジェクトの土台としては先細り
- 本アプリはキュー管理を自前で持つ必要がある（順列の永続化）ため、RNTP のキュー機能は元々あまり必要としない
- **Android のみ対応**のため、ネイティブ拡張が必要になっても iOS 版を書かなくてよく、コストが半分で済む

### 13.3 未解決の技術課題：通知/ロック画面の「次の曲」

expo-audio のロック画面コントロールは `showSeekForward` / `showSeekBackward`（±10秒シーク）のみを提供しており、
**次の曲 / 前の曲のボタンを出せない**（expo/expo#43538、2026-02 起票・未解決）。
要件 9.1「通知操作：次の曲」を満たすには対応が必要。

| 対応案 | コスト | リスク |
|---|---|---|
| **A. patch-package で expo-audio にパッチ** | 低 | expo-audio 更新のたびにパッチのメンテが必要 |
| B. 自前 Expo Module（Kotlin + Media3 MediaSession） | 高 | 実装量は増えるが自由度が高く、フェードもネイティブ化できる |
| C. MVPでは諦める（±10秒シークのみ） | ゼロ | RUSHの体験上、通知から次へ送れないのは痛い |

方針：**A で始め、破綻したら B へ移行**。issue #43538 に両プラットフォーム分の完全なパッチが提示されているため、A の初期コストは低い。

### 13.4 着手前に検証すべきこと（技術検証スパイク）

実装に入る前に、小さなプロトタイプで以下を確認する。

1. **区間再生の精度** — 再生位置の更新間隔で「20秒地点から35秒で切る」が破綻しないか
2. **フェードアウトの品質** — JS から `volume` を段階変更する方式で、聴感上なめらかか（不足ならネイティブ側へ）
3. **曲の切り替わりの間** — フェード終了から次曲再生までの無音がどの程度か。必要ならプレイヤー2枚持ちで先読みする
4. **バックグラウンド動作** — 画面ロック・スリープ中に再生が継続するか
5. **通知の「次の曲」** — 13.3 の案A（patch-package）が実際に動くか
6. **ライブラリ走査の速度** — 1000曲規模で expo-music-library の初回スキャンが実用的な速度か

## 15. 要確認事項（未決定・曖昧な点）

たたき台を読んでいて、実装に落とす前に決めておいた方がよさそうな点です。

1. ~~**区間指定は固定秒数か、曲の長さに対する相対（%）か**~~ → **決定（2026-09-02）**
   秒・％の両方に対応する。UI露出は秒＝Phase 1、％＝Phase 2。→ 4.2
2. ~~**開始位置＋再生時間が曲の長さを超える場合の挙動**~~ → **決定（2026-09-02）**
   曲の終端でフェードして次の曲へ。開始位置自体が曲より長い場合は0秒から再生。→ 4.2
3. ~~**自動スキップOFF時の挙動**~~ → **決定（2026-09-02）**
   自動スキップ＝RUSHモードのON/OFF。OFF時は区間再生を無効化し、曲を頭からフル再生する（A案）。→ 4.3
4. ~~**リピートの粒度**~~ → **決定（2026-09-02）／優先度：低**
   キュー全体のリピートのみ実装する。1曲リピートは「あってもなくてもよい」レベルのため対象外とし、必要になったら Phase 3 で検討する。
5. ~~**区間設定はキュー全体の共通設定か、曲ごとの個別設定か**~~ → **決定（2026-09-02）**
   全体設定を基本とし、曲ごとの個別設定を上書きとして持てる。個別設定が効くのは RUSH ON 時のみ。→ 4.2 / 4.3
6. ~~**曲一覧画面からの手動再生時、区間再生設定は適用されるか**~~ → **決定（2026-09-02）**
   普通のプレイヤー準拠とする。一覧から曲をタップしたら**その一覧をキューとして再生開始**し、RUSH ON なら区間再生、OFF ならフル再生。割り込み再生という特別扱いは設けない（シャッフル順は 6.2 の永続化で保持されるため不要）。→ 10.4
7. ~~**キュー作成後の画面遷移**~~ → **決定（2026-09-02）**
   「作成」押下後はプレイヤー画面へ自動遷移し、再生を開始する。→ 10.3
8. ~~**Android 13+ のメディア権限（READ_MEDIA_AUDIO）まわりの許可フロー**~~ → **決定（2026-09-02）**
   初回起動時にリクエストし、拒否時は説明画面＋設定アプリへの導線を表示する。→ 3.1
9. ~~**再生中に RUSH を ON/OFF 切り替えたときの挙動**~~ → **決定（2026-09-02）**
   次の曲から適用する。再生中の曲のシークし直しは行わない。→ 4.3
10. ~~**プレイヤー画面のスライダー操作は「全体設定の変更」か「その曲の個別設定の作成」か**~~ → **決定（2026-09-02）**
    スライダーは常に全体設定の変更。→ 4.2
11. **個別設定の識別キーと孤児データの掃除**（個別設定を実装する場合のみ／現在は保留）
    どのIDで曲を識別し（MediaStore ID を主キー＋パス・メタデータで再リンクする案）、端末から消えた曲の設定をいつ削除するか。
12. ~~**キュー作成画面とライブラリ画面の役割が重複しないか**~~ → **決定（2026-09-02）**
    専用画面は廃止し、ライブラリ画面の**長押し→複数選択**に統合する。アーティスト／アルバムをまとめて選んで簡易プレイリストとして流す導線は必須機能。→ 10.3
13. **秒⇄％ を切り替えたときの既存値の扱い**
    「20秒」を％に切り替えたとき、現在曲基準で換算するのか、変換せずデフォルト値に戻すのか。
14. ~~**再生時間（Length）よりフェード時間（Fade）が長い場合のクランプ**~~ → **決定（2026-09-02）**
    実効フェード時間 = `min(設定値, Length ÷ 2)`。→ 4.4
15. ~~**RUSH を OFF にした瞬間、再生中の曲の区間カットも解除するか**~~ → **決定（2026-09-02）**
    解除する。OFF時のみ現在曲のカットも即座に解除し、そのまま最後まで再生する（シークはしない）。→ 4.3
